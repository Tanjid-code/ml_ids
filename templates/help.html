🔬 How Detection Works

📏

Rule-Based Detection (Signatures)

264+ regex rules match known attack patterns in request data, headers, and payloads. Covers SQL Injection, XSS, and 13 other categories. Rules provide the severity classification (critical/high/medium/low).

🤖

ML Model Detection (XGBoost)

An XGBoost model trained on the UNSW-NB15 dataset classifies traffic as ATTACK or NORMAL. It uses 39 network features extracted from each request via psutil and HTTP data. The model does NOT determine severity — that comes from rules.

⚖️

Combined Detection

Both Detected: High confidence threat — rules provide severity.
Rule Only: Known attack pattern, ML missed it.
ML Only: Novel anomaly detected — classified as medium severity for investigation.
Both Normal: Clean traffic confirmed by both systems.

📈

Threshold Detection

Monitors rates: 100+ requests = DDoS, 5+ failed logins = Brute Force, 10+ unique ports = Port Scan.

❓ Frequently Asked Questions

Q: Why does ML show everything as "medium" severity?

A: The ML model only predicts ATTACK or NORMAL. It does not classify severity. Severity comes from rule-based detection. If only ML detects a threat (rules miss it), it defaults to "medium" for investigation.

Q: What does "Data Quality" mean on ML predictions?

A: The model needs 39 network features. Some (like TTL, jitter) can only be measured at packet level, so they are estimated. Data Quality shows what percentage of features are real vs estimated. Higher = more reliable prediction.

Q: Why are internal IPs (127.0.0.1) skipped by ML?

A: Internal/localhost traffic is the IDS system itself making API calls. Predicting on these would flood the system with false positives. Only external IPs are analyzed by the ML model.

Q: How do I generate a PDF report?

A: Go to Reports page, select "PDF Report" format, set your filters, and click Generate. Requires the fpdf2 package (pip install fpdf2).

Q: What is the Comparison page?

A: It shows a side-by-side comparison of rule-based and ML detections for each request. You can see where they agree, where rules catch something ML misses, and vice versa.

Q: Can the ML model make mistakes?

A: Yes. The model uses approximated features and may produce false positives or miss attacks. That's why we use it alongside rules — rules provide the authoritative classification, ML provides supplementary anomaly detection.
